# CLAUDE.md

Firmware for a sensor device on the Waveshare ESP32-S3-Touch-LCD-1.69 (ESP32-S3R8, 16MB flash, 8MB octal PSRAM, 240x280 ST7789V2 LCD, CST816T touch, QMI8658 IMU, PCF85063 RTC, buzzer, battery), measuring with external I2C sensors it detects by itself: INA219 / INA3221 current and voltage monitors, BME280 / BMP280 / BME680 / BME688 and AHT10 / AHT20 environment sensors, several at once. PlatformIO + Arduino-ESP32 core 3.x (pioarduino platform). Serves a configuration web UI and JSON API, persists settings in EEPROM, supports OTA, and shows a state-driven UI on the LCD. The WiFi/web/config code is ported from [ESP_LED_Controller](https://github.com/jaisor/ESP_LED_Controller) without its LED and MQTT parts.

## Build / flash

```bash
pio run                      # env waveshare_s3_lcd169 (the only one)
pio run -t upload
pio device monitor           # native USB CDC
```

There are no unit tests; verification means building and testing on hardware. `buildscript_versioning.py` runs pre-build and writes `include/version.h` (`SEMVER` env var, else `dev.<timestamp>`); the file is gitignored.

## Architecture

- [src/main.cpp](src/main.cpp) — `setup()`/`loop()` only: power latch, logging, factory-reset boot counter, creates `CDevice` then `CWifiManager`.
- [src/Board.h](src/Board.h) — every GPIO of the board. Values are for the "new" board revision (model printed on it); the old one differs in buzzer, RTC INT and power latch pins (noted inline).
- [src/Configuration.h](src/Configuration.h) / [.cpp](src/Configuration.cpp) — compile-time feature flags (`WIFI`, `SCREEN`, `BUZZER`, `TOUCH`, `SENSORS`, `WEB_LOGGING`, `DISABLE_LOGGING`), `configuration_t` + EEPROM load/save/wipe, timezone table (`TIMEZONES`, `CONFIG_getTzString()` → POSIX TZ strings).
- [src/Device.cpp](src/Device.cpp) — `DeviceState` state machine and the data screens show (`network_info_t`, battery voltage and `getBatteryPercent()` from a LiPo curve, boot progress). Every change bumps `getRevision()`; screens redraw when it moves. Also the power latch (`PWR_SYS_EN` held high), the buttons and buzzer: `handleButtons()` polls both buttons, `onButton()` passes the event to the display, then plays the matching sound (so a volume change made by the screen is heard); holding PWR for `POWER_OFF_HOLD_MS` (3s) powers off.
- [src/Button.cpp](src/Button.cpp) — `CButton`: debounced, non-blocking click / double click / long press (`BUTTON_*_MS`). `CLICK` is reported only after the double-click window (300ms) passes; `LONG_PRESS` fires while still held. A button already down at `begin()` (PWR, from switching on) is ignored until released. `ButtonId::BOOT` = GPIO0, `ButtonId::POWER` = PWR via `PWR_SYS_OUT`; RST is a hardware reset.
- [src/Touch.cpp](src/Touch.cpp) — `CTouch`: CST816T on the shared I2C bus (`Wire` is started in `CDevice::begin()`), polled every 15ms with the chip's auto-sleep disabled. Gestures (`TouchEvent`: TAP, DOUBLE_TAP, LONG_PRESS, SWIPE_LEFT/RIGHT/UP/DOWN) are classified from each touch's start and end points (`TOUCH_*` thresholds), not the chip's gesture register. Like the buttons, TAP is reported only after the double tap window (350ms) and LONG_PRESS fires while still touching (700ms without moving); the rest on lift. `CDevice::handleTouch()` passes them to the display and plays the matching sound (click / double / long) only if a screen acted on one. `TOUCH_MIRROR_X/Y` in Board.h flip directions if the panel is mounted mirrored.
- [src/sensors/](src/sensors/) — external sensors on the shared I2C bus, register-level drivers (no sensor libraries); `I2C_*()` helpers in [I2C.cpp](src/sensors/I2C.cpp).
  - `CSensors` ([Sensors.cpp](src/sensors/Sensors.cpp)) — owned by `CDevice`. Scans at boot and every `SENSOR_SCAN_MS` (5s) for hot-plugged sensors, probing only the supported chips' addresses (0x38-0x39, 0x40-0x4F, 0x76-0x77) and identifying devices by ID registers where they have them (`identify()`: INA3221 by TI manufacturer / die ID at 0x40-0x43; BME280 / BMP280 / BME68x by chip ID; AHT by soft reset + calibration bit; the INA219 has none, so anything at 0x40-0x4F without TI's IDs is reset and tried as one). A device not identified in `SENSOR_IDENTIFY_TRIES` (3) scans is left alone until it leaves the bus. Up to `SENSOR_MAX` (8) sensors, sorted by address. One that stops answering goes offline (retried every 5s) and is dropped after `SENSOR_REMOVE_MS` (60s). `loop()` returning true (sensor added / dropped / offline / back) bumps the device revision; `getListRevision()` moves only when sensors are added or dropped. The list changes only in `loop()`: other tasks (web) use `forEach()`, which holds its mutex. `SENSOR_format*()` give the UI's scaled value + unit (units starting with `^` are degrees, see `UI_drawValue()`).
  - `CSensor` ([Sensor.h](src/sensors/Sensor.h)) — one chip at one address: `init()` (identify + configure, also the retry), `run()` each loop, online / offline tracking, `getSample()` bumps on each published value (pages redraw on it), `getId()` is unique per run (pages hold ids, not pointers, since sensors can be dropped). `SensorModel` is not persisted.
  - `CPowerSensor` ([PowerSensor.cpp](src/sensors/PowerSensor.cpp)) — 1-3 channels: polls `readChannels()` every 50ms, publishes averages every 200ms (`power_reading_t`), 100-value current history per channel (20s). `CINA219` (32-sample averaging, 32V / 320mV) and `CINA3221` (3 channels, 16x 1.1ms averaging, ~106ms per set); current = shunt voltage / `configuration.ina219ShuntMilliOhm` / `ina3221ShuntMilliOhm`, read on every poll so web changes apply live.
  - `CEnvSensor` ([EnvSensor.cpp](src/sensors/EnvSensor.cpp)) — `EnvValue` TEMPERATURE / HUMIDITY / PRESSURE / GAS (NAN = unknown), one reading per `getInterval()`: `startMeasurement()`, wait `conversionMs()`, `readMeasurement()` (BUSY = ask again, up to 1s). History of 100 points, each the average of `ENV_HISTORY_MS` (6s) = 10 min. `CBME280` (also BMP280; normal mode, read every 1s), `CBME68x` (BME680 / BME688 by variant ID; forced mode every 3s with the hot plate at 320C for 150ms, raw gas resistance - no BSEC / IAQ), `CAHTx0` (AHT10 / AHT20 told apart by the CRC byte only the AHT20 sends; every 2s, the datasheets' self-heating limit). Compensation formulas are Bosch's floating point ones.
- [src/Buzzer.cpp](src/Buzzer.cpp) — `CBuzzer`: passive buzzer on LEDC PWM. Sounds are static `buzzer_note_t` arrays (`{freq Hz, ms}`, 0 Hz = rest) listed in `SOUNDS[]` in `BuzzerSound` order; an `esp_timer` steps the notes so timing isn't stretched by display flushes. Volume (`configuration.buzzerVolume`, 0 mutes) sets the duty cycle.
- [src/display/](src/display/) — LCD UI.
  - `CDisplay` ([Display.cpp](src/display/Display.cpp)) owns the Arduino_GFX ST7789 driver, a full-screen `Arduino_Canvas` framebuffer (134KB, PSRAM), the backlight PWM and the screens. `screenForState()` maps each `DeviceState` to a `ScreenId` — **the place to add state-driven screens**: INITIALIZING → `BOOT`, WIFI_AP_CREATED → `WIFI_STATUS` (setup instructions, BOOT click or double tap continues to `HOME`), everything else → `HOME`. `onStateChanged()` also flashes the IP on connect and "WiFi lost" on a drop. `showMessage()` draws a temporary overlay on any screen.
  - `CScreen` ([Screen.h](src/display/Screen.h)) — base class: `draw(gfx)` paints the whole screen (canvas is cleared first, flushed after); `update()` returns true to request a redraw (default: device revision or clock minute changed); `onButton()` receives button gestures while the screen shows (return true to redraw). Redraws are capped at ~30 fps.
  - [UI.h](src/display/UI.h) — palette, fonts (`UI_FONT_*`), layout (`UI_CONTENT_TOP`, `UI_BODY_TOP`/`BOTTOM`: everything under the status bar is content), `UI_drawCentered()`, and shared pieces: the status bar (WiFi state / clock / battery icon + %), page dots, level bar, chevrons.
  - [screens/](src/display/screens/) — `CBootScreen` (INITIALIZING), `CWifiScreen` (setup mode instructions; it still draws connecting / connected / offline variants but is only shown for AP mode), `CHomeScreen` (status bar + page carousel).
  - `CHomeScreen` ([HomeScreen.cpp](src/display/screens/HomeScreen.cpp)) — pages: one per detected sensor (`CPowerPage` / `CEnvPage`, or `CNoSensorPage` when there are none), Settings, Help. `syncSensorPages()` rebuilds the sensor pages when `CSensors::getListRevision()` moves, keeping the page being shown (an opened page whose sensor is dropped closes). Browsing: PWR click or swipe left = next page (slides in from the right, wraps), PWR double click or swipe right = previous, BOOT click or double tap = open. Opened, buttons go to the page until it returns `PageAction::EXIT`, and a long press on the screen closes the page from any depth; other touches are ignored.
  - [pages/](src/display/pages/) — `CPage` ([Page.h](src/display/pages/Page.h)): `drawCard()` for the carousel (draw relative to the given box, it slides partly off-screen), `drawContent()`/`onButton()` when opened. **No titles, back arrows or button hints on screen** (by design): pages keep to the button convention and the Help page documents it. Button convention inside pages: PWR click = next / increase, PWR double = previous / decrease, BOOT click = select / confirm, BOOT long press = back (EXIT at the top level).
    - `CSensorPage` ([SensorPage.h](src/display/pages/SensorPage.h)) — base of the sensor pages: title "<model> 0x<address>" on the card, looks its sensor up by id (`sensor()`, nullptr once dropped), redraws on each published sample, status card / content when there are no values (reading / not responding).
    - `CPowerPage` — card: one channel = current big, voltage and power; INA3221 = a row per channel. Opened: a channel's current big, voltage and power, 20s current graph; PWR / 2x PWR change channel.
    - `CEnvPage` — card: temperature big, then humidity / pressure / gas as the sensor has them. Opened: one value big with its min / max and a 10 min graph; PWR / 2x PWR change the value (dots at the bottom).
    - `CNoSensorPage` — stands in for the sensor pages while none are found: where to connect one.
    - `CHelpPage` — how the buttons, swipes, Settings, power and web setup work, in sections (`SECTIONS[]`; PWR / 2x PWR step through them). **Update it when controls change.**
    - `CSettingsPage` — menu (WiFi, Sensor, Brightness, Sound, About, Back) with one view per item. WiFi shows the network / setup AP details and can forget the network (`CDevice::forgetWifi()`: clears it, saves, restarts into setup mode). Brightness and Sound edit `configuration` live in steps of 10 and save to EEPROM on leaving the view. Sensors lists what was found (name, address, OK / Lost); the shunts are set on the web Device page.
  - [fonts/](src/display/fonts/) — Adafruit GFXfont headers, included only from [Fonts.cpp](src/display/Fonts.cpp) and declared `extern` in [Fonts.h](src/display/Fonts.h).
- [src/wifi/WifiManager.cpp](src/wifi/WifiManager.cpp) — STA connect with soft-AP fallback (`LoriiniSensor_<chip id>` / `password123`, 192.168.4.1), ESPAsyncWebServer routes, NTP via POSIX TZ, ElegantOTA Pro (paid, private repo; README describes switching to the free library) at `/update`. Pushes network info and state into `CDevice`. HTML templates in [HTMLAssets.cpp](src/wifi/HTMLAssets.cpp), Pico CSS in [CSSAssets.cpp](src/wifi/CSSAssets.cpp).

### Web routes
`/` (status; the sensors section is rendered from `/api` every second), `/wifi` (saves and reboots), `/device` (name, timezone, screen brightness, button sounds volume, detected sensors, INA219 / INA3221 shunts; saves without reboot), `/style.css`, `/log` (if `WEB_LOGGING`; reading clears it), `/api` (status JSON, with a `sensors` array: model, name, address, kind (power / environment), status (ok / offline); power: `channels[]` of voltage_v, current_a, power_w, over_range; environment: temperature_c, humidity_pct, pressure_hpa, gas_ohm as measured), `GET /config` (settings JSON, no WiFi password), `POST /config` (JSON import via `updateConfigFromJson()`, validated on a copy, saves and reboots), `POST /factory_reset`, `POST /reboot`, `/update` (OTA).

## Conventions and gotchas

- Adding a sensor: a `SensorModel` (plus name and id in Sensor.cpp), a `CPowerSensor` or `CEnvSensor` subclass, and a case in `CSensors::identify()` (and its address in `SCAN_ADDRESSES` if new). Identify by ID registers before writing anything where the chip has them: other chips share these addresses. Pages follow from the sensor's kind. Help page and README list the supported sensors.
- **`configuration_t` is raw-`EEPROM.put` serialized.** Adding/reordering/resizing fields shifts the layout and corrupts saved settings. The `_loaded == "lsens1"` marker identifies a valid config. Add new fields at the end, after `_loaded`, in a block with its own marker string; set defaults in `EEPROM_loadConfig()` when that marker is missing, range-check them there, and add them to `/config` GET and `updateConfigFromJson()`.
- Factory reset: 3 boots that don't survive `FACTORY_RESET_CLEAR_TIMER_MS` (2s) wipe EEPROM. Counter is EEPROM byte 0; config starts at byte 1.
- Web handlers run on the AsyncTCP task, not `loop()`. Don't drive the display or other hardware from them: change `configuration` / call `CDevice::configChanged()` and let the loop pick it up (as screen brightness does in `CDisplay::loop()`).
- The display is only drawn from `loop()` (and `setBootProgress()` during setup). Screens never call `flush()`; keep `draw()` free of blocking work.
- The panel has ~43px-radius rounded corners: keep text centered or inside `SCREEN_SAFE_INSET`; the status bar row (y 12-28) only loses ~13px to them, so its icons sit 24px from the sides.
- The LCD is 240x280 in a 240x320 controller: `LCD_ROW_OFFSET` 20.
- `CDevice::initHardware()` must stay first in `setup()`: on battery the board loses power when PWR is released unless `PWR_SYS_EN` is high. Keep `BUZZER_PIN` low when idle (the passive buzzer heats up otherwise) - `CBuzzer` leaves it at 0% duty between sounds.
- LEDC shares a timer between channels attached with the same frequency and resolution, and `ledcWriteTone()` retunes the whole timer. The buzzer attaches at `BUZZER_IDLE_HZ` (2 kHz) after the backlight (5 kHz) to get its own timer; don't use the backlight's frequency for notes or attach other PWM at the buzzer's.
- The fonts are 7-bit ASCII: no `·`, `›`, `°` or arrows in on-screen strings - draw them (`UI_drawChevron()`). Check new strings fit: the panel is 240px with rounded corners, so lines low on the screen get narrow (Help rows start at x=30 and must stay under ~184px). Widths can be computed from the `xAdvance` column of the font headers.
- Feature flag names (`WIFI`, `SCREEN`, `BUZZER`, ...) are macros: don't use them as enum values or identifiers.
- HTML templates are `printf` formats: literal `%` is `%%`, and the argument list must match the comment above each template.
- Logging uses ArduinoLog (`Log.infoln`, ...). The `while (!Serial)` wait in `setup()` is bounded on purpose (USB CDC).
- Style: classes prefixed with `C`, 2-space indent, `#pragma once`; feature code guarded with `#ifdef SCREEN` / `BUZZER` / `TOUCH`, and the firmware builds with each of those off. Turning `WIFI` off doesn't build yet (`CWifiManager` and `main.cpp` aren't guarded).

## Not implemented yet

IMU, RTC, MQTT. Temperature is Celsius only; the BME68x gas value is raw resistance (no IAQ). Touch is used in the carousel (swipe, double tap, long press); single taps and vertical swipes are detected but unused.
